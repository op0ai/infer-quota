Secret lookup lives in the `quota-secrets` crate. `quota-ctl` is the human CLI. `quotad` does not store passwords, API keys, or JWTs. The full note, including what must never be committed, is [`docs/SECRETS.md`](https://github.com/op0ai/infer-quota/blob/main/docs/SECRETS.md). This page follows that file.

## Lookup order

First hit wins:

1. **OpenBao** (optional) — KV v2, for material the companion adds. A default `quotad` that only reuses existing CLI sessions does not need it. `cargo test` does not need it.
2. **OS keychain** — macOS Keychain / Linux secret-service. The trait is in the tree. Security.framework is not linked. Off macOS the backend returns unimplemented.
3. **CLI files**, read-only, last — `$CODEX_HOME/auth.json` or `~/.codex/auth.json`, and `$CLAUDE_CONFIG_DIR/.credentials.json` or `~/.claude/.credentials.json`.

File writes are refused. `codex login` and Claude Code `/login` own those files.

Account metadata on the socket may include `secret_ref` `{ backend, path }`. That is a pointer. The bytes go through `quota-ctl secret put`.

## Local OpenBao

Dev only. The compose file is not a production vault. The token below is a dummy labelled as such.

```bash
docker compose -f docker-compose.dev.yml up -d
export QUOTA_OPENBAO_ADDR=http://127.0.0.1:8200
export QUOTA_OPENBAO_TOKEN=dev-only-not-for-prod
export QUOTA_OPENBAO_MOUNT=secret
export QUOTA_OPENBAO_PREFIX=quota
quota-ctl secret backends
export QUOTA_PUT=sk-example-not-real
quota-ctl secret put codex/work --from-env QUOTA_PUT
quota-ctl secret get codex/work
```

`secret get` prints `backend=` and `present=true`. It does not print the value.

The HTTP client in `quota-secrets` speaks plain HTTP. For TLS, put a proxy in front or extend the scaffold. The crate feature `openbao` is reserved and currently empty: the HTTP client always compiles so tests can cover URL parsing without a live server.

Default `cargo test --workspace` does not start OpenBao and does not open sockets to port 8200.
